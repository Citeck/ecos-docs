Описание действий
~~~~~~~~~~~~~~~~~~~

Для приостановки, возобновления и удаления экземпляра, а также изменения его переменных необходимо право ``bpmn-process-instance-edit``. Для миграции токенов требуется право ``bpmn-process-instance-migrate``.

"""""""""""""""""""""""""""""""""""""""""

.. _token_migration:

Миграция токенов
""""""""""""""""""

Миграция токенов используется для ручного управления ходом экземпляра процесса: отката на предыдущий шаг, пропуска ошибочного шага и повторного выполнения шага. Токен показывает, на каком элементе схемы сейчас находится экземпляр процесса.

Все действия выполняются в окне **«Миграция токенов»**, которое открывается из действий экземпляра процесса.

.. rubric:: Откат на предыдущий шаг

1. Нажмите на схеме на элемент, на котором сейчас находится экземпляр процесса (он отмечен счётчиком), и выберите **«Начальный токен»**.
2. Нажмите на ранее пройденный элемент, к которому нужно вернуться, и выберите **«Целевой токен»**.
3. Нажмите **«Мигрировать»** и подтвердите действие.

Текущий шаг будет отменён, экземпляр процесса продолжит выполнение с выбранного элемента.

.. rubric:: Пропуск ошибочного шага

1. Нажмите на схеме на элемент, на котором экземпляр процесса остановился, и выберите **«Начальный токен»**. Для инцидента этот элемент указан в колонке **Элемент** на вкладке :ref:`Инциденты <process_instance_incidents>`.
2. Нажмите на элемент, следующий за ошибочным шагом, и выберите **«Целевой токен»**. Ошибочный шаг указан в колонке **Отказавший элемент**.
3. Нажмите **«Мигрировать»** и подтвердите действие.

Ошибочный шаг выполнен не будет, экземпляр процесса продолжит выполнение со следующего элемента.

.. rubric:: Повторное выполнение шага

1. Нажмите на схеме на элемент, который нужно выполнить заново, и выберите **«Начальный токен»**.
2. Нажмите на этот же элемент ещё раз и выберите **«Целевой токен»**.
3. Нажмите **«Мигрировать»** и подтвердите действие.

Шаг будет запущен заново.

.. rubric:: Что учитывать при миграции

- Переменные процесса сохраняются. Удаляются только локальные переменные отменённого элемента.
- Целевой элемент запускается сразу после подтверждения. Если нужно исправить значения переменных, сделайте это до миграции (см. :ref:`Переменные <process_instance_variables>`).
- Действия, которые процесс уже выполнил, не отменяются: например, изменение статуса и атрибутов документа, отправленные уведомления.

Чтобы остановить выполнение экземпляра, используйте действие **«Приостановить экземпляр процесса»**, чтобы продолжить — **«Возобновить экземпляр процесса»**. Прекратить выполнение полностью можно действием **«Удалить экземпляр процесса»**.

Для миграции токенов необходимо право ``bpmn-process-instance-migrate``, для просмотра экземпляра процесса — ``bpmn-process-instance-read``. Права выдаются группам и пользователям на раздел, в котором находится модель процесса (см. :ref:`Права доступа <bpmn_permissions>`). Поэтому откат может выполнять ответственный за процесс без прав администратора системы.

   .. image:: _static/adm_29.png
      :width: 600
      :align: center

   На схеме начальный токен будет отмечен зеленой рамкой, целевой — красной. Также выбранные токены отражены в нижней части:

   .. image:: _static/adm_30.png
      :width: 600
      :align: center

   Нажмите **«Мигрировать»**. Подтвердите действие:

Инциденты
~~~~~~~~~~~~~~~~~~

На вкладке представлен список неразрешенных инцидентов (возникших ошибок) данного экземпляра процесса:

Для каждого инцидента показаны текст ошибки (**Сообщение**), экземпляр процесса, дата и время возникновения (**Дата создания**), шаг процесса, на котором произошла ошибка (**Элемент** и **Отказавший элемент**), тип инцидента и примечание. Входные данные шага доступны на вкладке :ref:`Переменные <process_instance_variables>` с фильтром по области видимости элемента.

Действия по исправлению: комментарий к инциденту, :ref:`изменение количества попыток <process_instance_retries>` (повторный запуск задания), :ref:`изменение переменных <process_instance_variables>` и :ref:`миграция токенов <token_migration>` (повтор или пропуск шага).

Для добавления комментария к инциденту и изменения количества попыток выполнения задания необходимо право ``bpmn-process-instance-edit``.

Изменение количества попыток
""""""""""""""""""""""""""""""

.. image:: _static/adm_37_2.png
    :width: 30
    :align: left

Изменить количество попыток выполнения неуспешной задачи:

.. image:: _static/adm_40.png
    :width: 500
    :align: center

Введите положительное количество оставшихся попыток (не менее 1) и нажмите **«Сохранить»**. Введённое значение устанавливает количество оставшихся попыток выполнения задания. Положительное значение позволяет исполнителю повторно получить задание при соблюдении остальных условий выполнения. Сохранение количества попыток само по себе не запускает задание немедленно.
