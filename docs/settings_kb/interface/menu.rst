.. _menu:

Меню
=====

.. contents:: Содержание
   :depth: 7

**Меню** — навигационная панель Citeck, которая отображается слева в интерфейсе и обеспечивает быстрый доступ к журналам, дашбордам, канбан-доскам, базам знаний и другим разделам системы.

Конфигурация меню гибко настраивается под группы пользователей: каждой группе или конкретному пользователю назначается собственная конфигурация. Поддерживаются три независимо настраиваемых блока — левое меню, меню «Создать» и пользовательское меню.

Статья описывает алгоритм выбора конфигурации меню для пользователя, структуру и версии конфигураций, типы элементов меню, настройку приоритетов групп, а также типичные проблемы при конфигурировании.

Зависимости настроек
--------------------

.. important::

 На отображение влияют настройки:
 
 * **Интерфейс основного меню (Журнал Конфигурация)** - глобальная настройка, для всего приложения и всех пользователей.
 * **Приоритеты групп (Настройки меню > Глобальная настройка)** - глобальная настройка для всех конфигураций и пользователей.
 * **Группы или пользователи (Настройки меню > Текущая конфигурация)** - принадлежность одной конфигурации меню.
 * **Доступность раздела (Настройки меню > Настройки конфигурации > Элементы меню > Раздел)** - принадлежность одного раздела пользователям.
 * **Рабочие пространства** с релиза 2025.1.2


Выбор меню для пользователя
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

Конфигурацию выбирает серверный источник ``uiserv/rmenu``. Клиент читает ``main-menu-type``, определяет версию модели (по умолчанию ``1``) и передаёт в запрос имя пользователя, версию и контекст рабочего пространства:

.. tab-set::

   .. tab-item:: Рабочие пространства выключены

      Клиент передаёт ``user`` и ``version``. Поле ``workspace`` в запрос не включается.

   .. tab-item:: Рабочие пространства включены

      Вместе с ``user`` и ``version`` передаётся ``workspace`` — текущее рабочее пространство. Это правило действует и для пространства ``default``: его наличие не означает, что механизм рабочих пространств выключен.

Сервер возвращает идентификатор конфигурации и разрешённую структуру ``subMenu``. Назначения ``authorities``, настройка ``menu-group-priority``, выбор конфигурации по умолчанию и разрешение совпадений обрабатываются сервером. Фронтенд не выполняет самостоятельный перебор персональных и групповых конфигураций.


Общий подход к настройке
~~~~~~~~~~~~~~~~~~~~~~~~

Основной подход к кастомизации меню под проект/модуль — создание нового меню с нужными элементами и назначениями. Приоритет относительно других подходящих конфигураций определяется серверными правилами выбора меню.

Версия конфигурации меню
~~~~~~~~~~~~~~~~~~~~~~~~~

В конфигурации меню есть поле **Версия модели**, которое определяет версию модели. Актуальный список версий:

 - **0** - устаревший xml формат конфигурации
 - **1** - актуальный json формат конфигурации

Дефолтные конфигурации меню
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

Ниже приведены примеры поставляемых конфигураций. Их наличие, состав и выбор для пользователя определяются серверной поставкой, а не фиксированным списком в ecos-ui:

1. **default-tasks** содержит все пункты из раздела :ref:`"Задачи"<tasks_spaces>` в дефолтном меню, включая сам раздел.
2. **default-data-lists** содержит все пункты из раздела :ref:`"Справочники"<datalists>` в дефолтном меню включая сам раздел.
3. **default-personal-ws-menu** содержит задачи (default-tasks) через пункт "Вложенное меню" (INCLUDE_MENU) и раздел "Разделы", куда добавлена ссылка на doclib (:ref:`библиотеку документов<ws_doc_library>`) с типом workspace-file и ссылка на :ref:`канбан доску<ws_kanban>` (kanban-task).
4. **default-ws-menu** содержит задачи (default-tasks) через пункт "Вложенное меню" (INCLUDE_MENU) и раздел "Разделы", куда добавлена ссылка на doclib (:ref:`библиотеку документов<ws_doc_library>`) с типом workspace-file и ссылка на :ref:`канбан доску<ws_kanban>` (kanban-task).

Доступность действий в журнале
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

Доступность редактирования, удаления, копирования, редактирования JSON и скачивания определяется списком действий журнала и серверными условиями доступа. Она может различаться для поставляемых конфигураций по умолчанию и пользовательских конфигураций.

Редактор интерфейса не поддерживает модель версии ``0``. Для модели версии ``1`` доступны описанные ниже настройки, если действие редактирования разрешено. Чтобы изменить поставляемое меню, создайте собственную конфигурацию или её копию с отдельным идентификатором.

Окно настроек
~~~~~~~~~~~~~~

Настройки содержат четыре вкладки:

#. **Настройки выбранной конфигурации** - описывает состояние отображаемого меню (элементы меню, версия, принадлежность и т.д.).
#. **Меню "Создать"** - для редактирования пунктов меню, доступных по нажатию на кнопку :guilabel:`Создать`
#. **Пользовательское меню** - для редактирования пунктов меню, доступных по нажатию на имя пользователя в правом верхнем углу.
#. **Глобальные настройки** - те настройки, что влияют на всю систему и всех пользователей (приоритеты).

~~~~~~~~~~~~~~~

.. important::

       Левое меню, меню «Создать» и пользовательское меню сохраняются в одной конфигурации ``subMenu`` (блоки ``left``, ``create`` и ``user``). У кнопки «Создать» дополнительно есть собственные назначения ``create.allowedFor``. Доступные типы элементов и правила вложенности у блоков различаются.

**************

Дочерние элементы вручную добавляются только в раздел. Создание нового раздела и разделяющего заголовка разрешено только на верхнем уровне. Для INCLUDE_MENU отдельного ограничения уровня нет: его содержимое раскрывается сервером. Полученная структура может отличаться от дерева, которое создаётся вручную в редакторе.

Доступность дополнительных характеристик:

- **Скрывать название** — для раздела верхнего уровня.
- **Иконка** — в левом меню на втором уровне, кроме разделяющего заголовка и INCLUDE_MENU. Для пунктов, добавленных из журналов, отображаемые сведения также могут поступать из связанной записи.
- **Свернуть раздел по умолчанию** и **Доступно для** — настройки раздела.
- Обычное редактирование не предлагается для JOURNAL, KANBAN, DOCLIB, PREVIEW_LIST и DASHBOARD. Для них доступны другие действия, например удаление пункта.

         Подробнее про `Абсолютные и относительные ссылки <https://htmlacademy.ru/blog/boost/frontend/links>`_.

      **HTTP/HTTPS URL** обычно открывается в новой вкладке браузера. При включённых рабочих пространствах наличие ``ws=`` в ссылке переводит её открытие в текущую вкладку браузера.

         :width: 400

      - Атрибут текущего рабочего пространства подставляется через ``${attrName}``, например ``/v2/journals?journalId=${attrName}``, если атрибут содержит идентификатор журнала.       .. image:: _static/menu/Menu_url_relative.png
         :width: 400
         :align: center

      - Для значения без начального ``/`` поведение зависит от рабочих пространств. При включённом механизме клиент разрешает ссылку относительно хоста и добавляет ``ws``. Без этой обработки действуют обычные правила относительных ссылок браузера; это не простое добавление строки к текущему URL.

         Чтобы путь не зависел от текущей страницы, используйте внутренний маршрут с начальным ``/``, например ``/v2/journals?journalId=contracts``.

Секция "Группы и пользователи"
*******************************

Выбор групп и пользователей, которым будет назначено редактируемое меню:

* Назначения сохраняются в ``authorities``. Если список пуст, клиент записывает ``GROUP_EVERYONE`` — назначение всем пользователям.
* При нескольких подходящих конфигурациях выбор выполняет сервер ``uiserv/rmenu``. Чтобы избежать неоднозначной настройки, используйте отдельные назначения и согласованный список приоритетов групп.
* Группы, указанные в конфигурациях, добавляются в список настройки приоритетов. Порядок можно изменить вручную.

В персональном рабочем пространстве (``ws`` содержит ``user$``) секция «Группы и пользователи» не отображается.

Секция "Приоритеты групп"
**************************

* Список объединяет группы из сохранённой настройки приоритетов и назначений конфигураций меню. ``GROUP_EVERYONE`` и персональные пользователи в список групп не включаются.
* Приоритет задаётся вручную перетаскиванием и сохраняется в ``menu-group-priority``. Клиент не вычисляет его автоматически по уровню группы в оргструктуре.
* Более специфичные группы и группы администраторов рекомендуется располагать в соответствии с нужным порядком выбора. Применение этого порядка и соотношение с персональными назначениями определяет сервер.

.. dropdown:: Как это работает
   :color: secondary

   В конфигурациях меню указываются назначения. Глобальная настройка приоритетов передаёт серверу порядок групп. Пример ниже иллюстрирует организацию назначений; конкретный результат подбора определяется серверными правилами.

   .. image:: _static/menu/menu_groups_1.png
      :width: 600
      :align: center

   **АП** - авторизованный пользователь

   1. Для персонального меню tam42 назначьте его пользователя конфигурации №10. Не создавайте несколько конкурирующих персональных назначений без необходимости.

   2. Для меню администраторов назначьте соответствующую группу конфигурации №3 и задайте нужное положение группы в приоритетах.

   3. Если пользователь входит в группы «Клерки» и «Главные клерки» с разными меню, разместите более специфичную группу в соответствии с желаемым приоритетом и проверьте итоговое меню под этим пользователем.

   4. Конфигурацию по умолчанию при отсутствии подходящих назначений выбирает сервер с учётом рабочего пространства и версии меню.

Решение возможных проблем
---------------------------

.. dropdown:: Несколько подсвеченных элементов меню
   :color: secondary

   В меню должен быть подсвечен только активный (выбранный) журнал.

   Но может быть ситуация, что при выборе одного элемента подсвечиваются несколько элементов меню сразу:

   .. image:: _static/menu/active_01.png
      :width: 300
      :align: center

   Такое происходит, если при конфигурации меню использовалось копирование ui-элементов без изменения их **id**.

   .. image:: _static/menu/active_02.png
      :width: 500
      :align: center

   Логика у UI следующая - подсвечивается синим открытый в данный момент элемент. И если id задублированы, то все элементы с данным id будут подсвечены.

   Поэтому необходимо следить за уникальностью id элементов, и если элементы копируются, то для получения уникальных id использовать онлайн генераторы:

   .. image:: _static/menu/active_03.png
      :width: 300
      :align: center
