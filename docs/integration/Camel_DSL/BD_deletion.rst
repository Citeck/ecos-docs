Удаление данных из БД
=======================================

Для удаления данных из БД необходимо создать **Credentials**, **Источник данных** и **Camel DSL** так же, как описано в разделе **«Выборка из БД»**. Содержимое маршрута должно включать SQL-запрос на удаление данных.

.. contents::
   :depth: 2

Простое удаление записей
--------------------------

Маршрут **clearValues** удаляет все записи из таблицы **simple** источника данных **datasource**, кроме записей с **id** равным **'1'** или **'2'**:

.. code-block:: yaml

  - route:
      id: "clearValues"
      from:
        uri: "timer:start?delay=-1&repeatCount=1"
        steps:
          - setBody:
              constant: "delete from simple where id not in ('1','2')"
          - to: "jdbc:datasource"

Выборка с последующим удалением
---------------------------------

При переносе данных в Citeck удаляйте только те исходные записи, для которых подтверждено успешное сохранение в целевом источнике:

1. Выберите записи и сохраните их первичные ключи вместе с данными, которые будут перенесены.
2. Преобразуйте данные в атрибуты целевых записей и сохраните их через :ref:`ecos-records-mutate <EcosRecordsMutateEndpoint>`. При ошибке сохранения этот компонент передает исключение в маршрут; заголовок ``recordsMutated`` содержит ссылки на успешно сохраненные записи после успешного вызова.
3. Только после подтверждения сохранения удалите соответствующие исходные записи по сохраненным ключам. Для SQL используйте параметры JDBC; не подставляйте значения ключей в текст запроса конкатенацией строк.

.. warning::

   Не выполняйте ``delete from simple`` без условия внутри ``split``: такой запрос очищает всю таблицу уже после первого элемента. Перенос этого запроса за пределы ``split`` также не защищает от удаления новых записей, добавленных параллельно с переносом.

   :ref:`RecordsDaoEndpoint <camel_dsl_records_dao_endpoint>` перехватывает ошибки сохранения и только пишет их в лог. Успешное завершение вызова этого бина не подтверждает запись данных, поэтому следующее за ним удаление может привести к потере исходных записей.

Запись через Records API и удаление через JDBC не образуют общую транзакцию автоматически. Предусмотрите повторный запуск после сбоя между этими операциями: сохранение по стабильному ключу должно быть идемпотентным, а исходные записи — защищены от изменения или проверены перед удалением. Обработчик ошибок маршрута не должен считать неудачное сохранение успешным и продолжать удаление.

.. note::

   Camel не меняет регистр SQL, заданного в ``constant``. В PostgreSQL незаключенные в двойные кавычки идентификаторы приводятся к нижнему регистру самой СУБД. Если колонка создана с именем ``"COMPANY_ID"``, обращайтесь к ней с кавычками: ``select * from simple order by "COMPANY_ID"``.
