.. _common_lib:

Общая библиотека для обработки EDI событий ecos-edi-integration
================================================================

.. note::

    Доступно только в Enterprise версии.

Библиотека ``ecos-edi-integration`` обрабатывает унифицированные EDI-события в Citeck: вложения, подписи и пакеты документов. При запуске OSGi-бандла создаётся отдельный Camel-контекст с входной точкой ``direct-vm:ecosEventsReceiveVmRoute``.

Исходный код: `ecos-edi-integration <https://gitlab.citeck.ru/citeck-projects/ecos-edi-integration>`_.

Версия и совместимость
----------------------

Описание сверено с версией **1.9.0**. В её POM заданы **Camel 3.11.2**, **ecos-osgi-loader 2.0.0** и **ecos-edi-commons 2.15.0-SNAPSHOT**. Эти зависимости имеют scope ``provided``: необходимые API и компоненты должны быть доступны в принимающем окружении.

.. important::

    Перед установкой проверьте версии API, экспортируемые OSGi-пакеты и наличие компонента ``direct-vm`` на целевом стенде. Общая :ref:`инструкция загрузки OSGi-бандлов <OSGI>` описывает также окружение с Camel 4, где ``direct-vm`` удалён. Совместимость библиотеки 1.9.0 с таким окружением не подтверждена. Замена ``direct-vm`` на ``direct`` сама по себе не сохраняет обмен между отдельными Camel-контекстами.

Подключение событий
-------------------

Запуск бандла создаёт обработчик, но получение событий у провайдера настраивается отдельно. В поле **Camel endpoint** отправляющей синхронизации укажите ``direct-vm:ecosEventsReceiveVmRoute``. Пример настройки: :ref:`получение событий из ящика Контур.Диадок <events_kontur>`.

В стандартной фабрике версии 1.9.0 зарегистрированы обработчики **KONTUR**, **CORUS** и **SBIS**. Наличие обработчика не означает поддержку всех возможностей API соответствующего провайдера.

Тело сообщения должно представлять унифицированное событие ``ru.citeck.ecos.domain.edi.dto.Event`` из совместимой версии ``ecos-edi-commons``. Общий процессор проверяет:

* наличие ``ediProviderType``;
* наличие зарегистрированного обработчика этого провайдера;
* непустой идентификатор собственного ящика в ``ourId.attributes.boxId``.

При нарушении этих условий процессор выбрасывает ``IllegalArgumentException``. Исходные ответы провайдера необходимо преобразовать в унифицированное событие до передачи в этот маршрут.

Условия работы
---------------

Библиотека получает ``RecordsServiceFactory``, ``RecordsService`` и ``EdiService`` из Spring-контекста принимающего приложения. В данной версии используются Alfresco-источники и модель данных: конфигурация EDI читается из ``alfresco/`` с типом ``ediConfig:ecosConfig``, а поиск контрагентов использует ``alfresco/counterpartyByBoxId``. Эти сервисы, источники и используемые Alfresco-пути хранения должны быть доступны в окружении.

События проходят по цепочке:

.. code-block:: text

    direct-vm:ecosEventsReceiveVmRoute
        -> direct:ecosEventsRedistributesRoute
        -> direct:ecosCommonEventRoute

Доставка в маршрут не всегда приводит к обработке пакета. При ``inboundPackagesProcessing=BOX_ID`` внешнее событие без найденного контрагента пропускается с сообщением ``Skip event``. Для внутреннего пакета эта проверка не блокирует обработку. При других значениях режима отсутствие контрагента само по себе не блокирует вызов процессора. Значение режима по умолчанию — ``ALL``.

Порядок загрузки бандла описан в разделе :ref:`Функционал загрузки OSGi-пакетов <OSGI>`. Загрузку выполняйте от имени системного администратора после проверки совместимости окружения.
