Описание ecos-edi-kontur
================================================================================

Библиотека ``ecos-edi-kontur`` обеспечивает интеграцию с сервисами Контур.Диадок и Контур.EDI. Maven-координаты: ``ru.citeck.ecos:ecos-edi-kontur``.

Описание ниже сверено с исходниками версии ``2.8.1``, использующей ``ecos-edi-commons:3.8.0``.

Документация сервисов:

    - `https://api-docs.diadoc.ru/ru/latest/  <https://api-docs.diadoc.ru/ru/latest/>`_
    - `API EDI.Контур documentation <https://edi-api-documentation.readthedocs.io/en/latest/>`_

Веб-интерфейсы сервисов:

    - `Вход в систему <https://diadoc.kontur.ru/>`_
    - `Тестовый Контур.EDI <https://test-edi.kontur.ru/SelectParty>`_
    - `Контур.EDI <https://edi.kontur.ru/SelectParty>`_

Настройка подключения
--------------------------------------------------------------------------------

Для Диадока и Контур.EDI создаются отдельные конфигурации ящиков и синхронизаций. В конфигурации ящика выберите провайдера **Контур** (``KONTUR``) и заполните параметры подключения:

.. list-table::
    :widths: 25 40 35
    :header-rows: 1
    :class: tight-table

    * - Параметр
      - Контур.Диадок
      - Контур.EDI
    * - Источник данных (``datasourceRef``)
      - Базовый URL API Диадока.
      - Базовый URL API Контур.EDI.
    * - Авторизационные данные (``credentialsRef``)
      - Credentials с заполненными ``username`` и ``password``.
      - Credentials с заполненными ``username`` и ``password``.
    * - Идентификатор ящика (``boxId``)
      - Обязателен.
      - Обязателен.
    * - Ключ разработчика (``devKey``)
      - Обязателен.
      - Обязателен.
    * - GLN (``gln``)
      - В этом пути подключения не используется.
      - Обязателен дополнительно к остальным параметрам.

Пример настройки: :ref:`Настройка получения событий с ящиком Контур.Диадок <events_kontur>`. При использовании инструкции учитывайте версию механизма конфигурации в вашем экземпляре Citeck.

Выбор сервиса для синхронизации событий
--------------------------------------------------------------------------------

В версии ``2.8.1`` обычная синхронизация событий выбирает сервис по URL источника данных. Диспетчер ``KonturEventsSyncService`` читает URL из атрибута ``config.url`` записи, указанной в ``datasourceRef``, и выполняет проверки в следующем порядке:

1. Если URL содержит ``diadoc`` без учёта регистра, запускается синхронизация с Диадоком.
2. Иначе, если исходный URL содержит строчную подстроку ``edi``, запускается синхронизация с Контур.EDI. Эта проверка учитывает регистр.
3. Если ни одно условие не выполнено, выбрасывается ``IllegalArgumentException``.

Если URL содержит обе подстроки, приоритет имеет Диадок. Прокси-адрес без распознаваемых подстрок не пройдёт эту проверку. Не меняйте регистр URL целиком для обхода ограничения: путь URL может быть чувствителен к регистру.

Это правило относится к обычной синхронизации событий. Метод точечной синхронизации ``pointWiseSync`` в этой версии делегирует запрос в Диадок без выбора сервиса по URL.

Версии конфигурации ящиков
--------------------------------------------------------------------------------

Библиотека сохраняет два механизма чтения конфигурации:

* **v1** — устаревший ``KonturBoxInfoProvider``: URL читается из ``config.url`` источника данных, идентификатор ящика — из ``ourId.attributes.boxId``, а ``devKey`` и ``gln`` — из ``specialInfo``.
* **v2** — ``KonturBoxInfoDataProvider``: конфигурации получаются через ``EdiBoxDataService``, URL — через ``EdiDatasourceService``, а ``boxId``, ``devKey`` и ``gln`` хранятся в отдельных полях конфигурации ящика.

При поиске подключения к API библиотека сначала обращается к механизму v1, затем, если конфигурация не найдена, — к v2. При этом диспетчер обычной синхронизации событий в версии ``2.8.1`` продолжает читать ``config.url`` напрямую. Используйте конфигурацию, совместимую с версией библиотеки и микросервиса, в котором она подключена.
