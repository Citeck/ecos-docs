Конфигурация ЭДО
================================================================================

Описание ниже сверено с исходниками ``ecos-edi:1.14.0``. Настройки поставляются отдельными конфигурационными артефактами приложения. Их значения могут быть переопределены в установленном экземпляре Citeck.

Идентификаторы ящиков, источники данных и авторизационные данные задаются в конфигурациях ящиков. Пример: :ref:`Настройка получения событий с ящиком Контур.Диадок <events_kontur>`. При использовании инструкции учитывайте версию механизма конфигурации ящиков.

Основные настройки обработки документов
--------------------------------------------------------------------------------

Таблица описывает основные параметры подписи, фильтрации событий и обработки печатных форм. Она не является полным перечнем конфигурации микросервиса. В столбце «Поставляемое значение» указано значение из артефакта приложения.

.. list-table::
    :widths: 25 60 15
    :header-rows: 1
    :class: tight-table

    * - Параметр
      - Описание
      - Поставляемое значение
    * - ``edi-sign-content-type``
      - Определяет данные, подготавливаемые для электронной подписи: ``content`` — весь контент документа; ``digest`` — дайджест, вычисляемый на стороне сервера. В коде ветка дайджеста выполняется для любого значения, отличного от точной строки ``content``, включая отсутствие значения. Регистр учитывается.
      - ``content``
    * - ``inboundPackagesProcessing``
      - Определяет, допускается ли событие к обработке при отсутствии контрагента. В режиме ``BOX_ID`` невнутреннее событие пропускается, если контрагент не найден. В режиме ``ALL`` этот фильтр не отклоняет событие из-за отсутствия контрагента. Внутренние пакеты допускаются независимо от наличия контрагента. Подробнее см. ниже.
      - ``ALL``
    * - ``splitLsdfDocflowByLegalEntities``
      - При ``true`` поиск пакетов, вложений и подписей учитывает направление документооборота. Это позволяет раздельно обрабатывать входящие и исходящие представления при обмене между собственными юридическими лицами, если соответствующие события получены и допущены к обработке. При ``false`` разделение отключено. Сам флаг не создаёт входящее событие у провайдера.
      - ``true``
    * - ``allowGenerateLsdfPrintFormsAsyncOnFail``
      - При ``true`` разрешает отложенную генерацию печатной формы (ПФ), если провайдер вернул ``NOT_YET_GENERATED`` или ``UNKNOWN_ERROR``. Документ помечается для повторной генерации. При ``false`` для этих результатов выбрасывается исключение. Флаг не подавляет любые ошибки получения ПФ.
      - ``true``

Для ``splitLsdfDocflowByLegalEntities`` и ``allowGenerateLsdfPrintFormsAsyncOnFail`` используйте логические значения ``true`` и ``false``. Хотя артефакты поставляют ``true``, при отсутствии значения в соответствующем поле конфигурационного сервиса его метод возвращает ``false``.

Фильтрация событий по контрагенту
--------------------------------------------------------------------------------

Поиск выполняется через ``EcosCounterpartyService.findCounterpartyWithSourceId`` с учётом ссылки на синхронизацию. Если задан пользовательский источник ``counterpartySourceId``, поиск сначала выполняется в нём. При отсутствии результата используется поиск по идентификатору ящика контрагента, типу провайдера и активности записи ЭДО.

Значение ``BOX_ID`` сравнивается без учёта регистра. Любое другое значение не включает ограничение по наличию контрагента; при пустом или отсутствующем значении используется ``ALL``. Внутренний пакет определяется по признаку ``counterpartyId.attributes.internal`` и проходит этот фильтр независимо от режима.

В обработчике событий фильтр не ограничен отдельной проверкой входящего направления. Режим ``ALL`` снимает только ограничение по наличию контрагента: успешная загрузка документа также зависит от последующей обработки.

Отложенная генерация печатных форм
--------------------------------------------------------------------------------

Для современного хранилища документ помечается атрибутом ``ediDocInfo:needUpdatePrintForm``. В режиме legacy/Alfresco используется атрибут ``eint:needUpdatePrintForm``.

В микросервис входит штатная задача ``UpdatePrintFormJob``. Она регистрируется при запуске приложения и использует настройку ``ecos.job.update-print-form.cron``. Поставляемое cron-выражение ``0 0/3 * * * *`` задаёт запуск каждые три минуты; окружение может переопределить расписание.

Задача выбирает до 100 записей типа ``edi-document`` с ``ediDocInfo:needUpdatePrintForm=true`` за проход. После успешного сохранения ПФ флаг снимается. При результатах ``NOT_YET_GENERATED`` и ``UNKNOWN_ERROR`` документ остаётся для повторной обработки; при других ошибках типа ``PrintFormGenerationException`` повторная генерация отключается.

.. warning::

    При использовании отложенной генерации проверьте работу штатной задачи и её расписание. Её выборка рассчитана на ``edi-document`` с атрибутом ``ediDocInfo:needUpdatePrintForm``. Для документов legacy/Alfresco с атрибутом ``eint:needUpdatePrintForm`` требуется отдельно проверить наличие совместимого обработчика.
