Конфигурация ЭДО
==================

После переноса ЭДО в микросервис интеграции - большая часть конфигурации, вроде идентификаторы ящиков, креды и т.д. переместились из системного журнала **Конфигурация EDI**. Информацию по этой конфигурации можно найти :ref:`Настройка получения событий с ящиком Контур_Диадок<events_kontur>`

Актуальная конфигурация в журнале **"Конфигурация EDI"**:

.. list-table::
    :widths: 15 35 20
    :header-rows: 1
    :class: tight-table

    * - Параметр
      - Описание
      - Возможные значения
    * - ``signContentType``
      - Указывается, какая часть контента будет подписываться ЭЦП.
      - - **content** (по умолчанию) - подпись строится на основании всего контента документа целиком.
        - **digest** - подпись строится на основании "дайджеста" документа, который высчитывается на стороне бэкенда ECOS. ЭДО провайдер его, насколько известно, не понимает как подпись к документу.
    * - ``inboundPackagesProcessing``
      - Указывается, исходя из каких правил обрабатывать входящие документы.
      - - **BOX_ID** - при получении входящего документа обязательно ищет контрагента в системе, от которого пришел данный документ. Если контрагент не найден - документ не будет загружен, событие ЭДО будет пропущено. Контрагент ищется с помощью алгоритмов ``EdiCounterpartyService`` на основании активного провайдера.
        - **ALL** (или любое другое) - игнорирование отсутствия контрагента. Все документы будут загружаться в систему.
    * - ``splitLsdfDocflowByLegalEntities``
      - Зеркалирование. Включенный флаг обозначает, что исходящий пакет, отправленный в своё же юр. лицо, попадёт в систему ещё и как входящий. С технической стороны, при поиске вложений, пакетов, подписей ищем не просто по идентификаторам, но и по направлению.
      - - **true** - включено.
        - **false** (или любое другое) - выключено.
    * - ``allowGenerateLsdfPrintFormsAsyncOnFail``
      - Оптимизация. Разрешает генерировать печатную форму (ПФ) асинхронно, если ЭДО-провайдер не смог отдать её сразу при получении пакета. Актуально для проектов, у которых заказчикам приходит большой объём формализованных документов - для них в ассоциацию попадает оригинальная xml, а на генерацию ПФ нужно время. Флаг позволяет не прерывать работу интеграции, а проставить флаг ``eint:needUpdatePrintForm``.

        .. warning::

            Если в проекте нет джобы, которая будет регенерировать документы с таким флагом - печатные формы, не сгенерированные при получении, не будут получены вообще. См. Генерация печатных форм.
      - - **true** - включено.
        - **false** (или любое другое) - выключено.
