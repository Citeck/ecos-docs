Описание ecos-edi-sbis
================================================================================

Библиотека ``ecos-edi-sbis`` обеспечивает интеграцию с Тензор.СБИС для юридически значимого документооборота (ЮЗДО). Maven-координаты: ``ru.citeck.ecos:ecos-edi-sbis``.

Описание ниже сверено с исходниками версии ``2.11.0-SNAPSHOT``.

Ссылка на документацию:

- `Порядок работы с API-интерфейсом  <https://sbis.ru/help/integration/api/sequence>`_
- `список используемых в Тензор.СБИС форматов документов <https://sbis.ru/formats/edo/>`_

Ссылка на личный кабинет:

- `Тест  <https://fix-online.sbis.ru/>`_
- `Прод  <https://online.sbis.ru/>`_

Настройка подключения
--------------------------------------------------------------------------------

При создании конфигурации ящика заполните общие обязательные поля формы и выберите провайдера **СБИС** (``SBIS``). Укажите следующие параметры подключения:

.. list-table::
    :widths: 25 75
    :header-rows: 1
    :class: tight-table

    * - Параметр
      - Описание
    * - **URL** (``datasourceRef``)
      - Ссылка на источник данных с базовым URL сервиса.
    * - **Авторизационные данные** (``credentialsRef``)
      - Ссылка на credentials с заполненными атрибутами ``username`` и ``password``. Библиотека передаёт логин и пароль в JSON-RPC метод ``СБИС.Аутентифицировать`` и использует полученный идентификатор сессии для последующих запросов.
    * - **Идентификатор ящика** (``boxId``)
      - Идентификатор ящика СБИС, для которого настраивается подключение.

Базовый URL должен позволять добавление путей ``/auth/service/`` и ``/service/?srv=1``: библиотека формирует эти адреса самостоятельно. При прямом подключении укажите URL хоста выбранного контура без этих путей. При подключении через прокси используйте базовый адрес с согласованным префиксом пути.

Ключ разработчика (``devKey``) и GLN в этом пути подключения не используются.

В библиотеке сохранены два механизма чтения конфигурации ящика:

* **v1** — устаревший механизм: URL читается из ``config.url`` источника данных, а идентификатор ящика — из ``ourId.attributes.boxId``.
* **v2** — конфигурация получается через ``EdiBoxDataService``; URL извлекается через ``EdiDatasourceService``, а идентификатор ящика хранится в отдельном поле ``boxId``.

При поиске подключения библиотека сначала обращается к механизму v1, затем, если конфигурация не найдена, — к v2. Используйте поля и форму, соответствующие версии механизма в вашем экземпляре Citeck.

Настройка ящика задаёт параметры соединения. Для получения событий отдельно настройте синхронизацию и обработчик событий: сервис СБИС принимает конфигурацию синхронизации с ``stateServiceConfig.endpoint`` и передаёт обработанные события в ``EdiStateService``. Форма и расписание синхронизации определяются микросервисом, в котором используется библиотека.

Ограничения
--------------------------------------------------------------------------------

В версии ``2.11.0-SNAPSHOT`` стандартный генератор EDI XML возвращает ``null``, а оба метода отправки EDI XML — с подписью и без неё — выбрасывают ``UnsupportedOperationException``. Этот путь EDI-интеграции не реализован.

Доступность отдельных операций ЮЗДО зависит от реализованных методов и сценария обработки. Методы общего API ``acceptDocument`` и ``sendSimpleRejection`` для СБИС не поддерживаются и выбрасывают ``UnsupportedOperationException``. Это ограничение конкретных методов; возможность выполнить соответствующее действие другим сценарием необходимо проверять отдельно.
