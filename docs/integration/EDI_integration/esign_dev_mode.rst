.. _esign_dev_mode:

Отладочный режим электронной подписи
======================================

.. note::

    Доступно только в Enterprise версии.

.. warning::

    Режим предназначен исключительно для стендов разработки и тестирования. Подпись, полученная в этом режиме, **не является усиленной квалифицированной подписью** и не
    имеет юридической значимости. На продуктивном стенде режим должен быть выключен.

Зачем нужен
-------------

:ref:`Штатное подписание<esign>` работает через **КриптоПро ЭЦП Browser plug-in** и ключ в криптопровайдере на машине пользователя. На машине разработчика такого ключа обычно нет,
и получить его непросто: закрытый ключ ГОСТ должен быть создан внутри самого КриптоПро, импортировать его извне нельзя.

Из-за этого любой сценарий, где встречается подписание, не деградирует, а блокируется целиком: процесс невозможно провести дальше шага подписи. Отладочный режим подменяет
только криптографическую операцию — диалог выбора сертификата, запрос дайджеста, отправка подписи на сервер и обработка ошибок выполняются своим обычным путём.

Режимы
--------

Поведение задаётся конфигурацией Citeck с идентификатором ``esign-dev-mode`` приложения ``edi`` (полный ключ — ``app/edi$esign-dev-mode``). Значение — JSON:

.. list-table::
    :widths: 15 85
    :header-rows: 1
    :class: tight-table

    * - ``mode``
      - Поведение
    * - ``off``
      - Значение по умолчанию. Штатное подписание через КриптоПро.
    * - ``stub``
      - Сертификаты синтетические, подпись — маркерная строка. Криптографии нет вообще,
        внешние сервисы не вызываются. Годится, чтобы пройти процесс насквозь, но
        разобрать такую подпись платформа не сможет.
    * - ``remote``
      - Сертификаты и подпись берутся у :ref:`симулятора ЭДО<edi_sim>`. Подпись —
        настоящая отсоединённая CMS, платформа разбирает её и заполняет владельца,
        серийный номер, издателя и срок действия сертификата.

Для режима ``remote`` дополнительно задаётся ``url`` — адрес административного API
симулятора.

.. code-block:: json

    {
      "mode": "remote",
      "url": "/gateway/edi-sim/admin/api"
    }

.. important::

    ``url`` обязан быть путём того же источника — как правило, маршрутом gateway.
    Абсолютный адрес отвергается с ошибкой: в запросе на подписание уходит **содержимое документа**, а не его хэш, и вместе с ним — cookie сессии пользователя. Указание
    внешнего хоста означало бы передачу и того, и другого на чужой сервер.

    Чтобы адрес вида ``/gateway/edi-sim/…`` работал, симулятор должен быть :ref:`зарегистрирован в ECOS<edi_sim>`.

Изменение значения
--------------------

Артефакт конфигурации поставляется вместе с микросервисом ecos-edi со значением ``off``.
Значение меняется в журнале конфигураций Citeck, либо :ref:`патчем<ecos_artifacts>`:

.. code-block:: yaml

    id: esign-dev-mode-remote

    name:
      ru: Включить отладочный режим ЭП
      en: Enable e-signature debug mode

    target: app/config$app/edi$esign-dev-mode

    type: json
    config:
      operations:
        - { op: set, path: '$.value', value: { mode: remote, url: '/gateway/edi-sim/admin/api' } }

.. note::

    Значения конфигураций кешируются в браузере, поэтому изменение подхватывается не мгновенно — обновите страницу, если новое значение ещё не применилось.

Как это выглядит для пользователя
-----------------------------------

Режим не маскируется под обычное подписание:

- при первом обращении к подписанию на странице показывается предупреждение с указанием включённого режима;
- в диалоге выбора сертификата выводится баннер с тем же предупреждением;
- сертификаты в списке помечены — в наименовании владельца добавлено «(отладка)», в издателе и криптопровайдере указано, что это отладочный источник.

Ограничения
-------------

- Методы, которые режим не может подменить осмысленно (``signXml``, ``getHash``, ``signHash``, работа с файлами), возвращают явную ошибку, а не правдоподобный результат.
- Локальная проверка подписи всегда успешна: проверять нечего.
- В режиме ``stub`` подпись не является криптографической — платформа не сможет извлечь из неё данные сертификата.
- Список сертификатов фильтруется по сроку действия — так же, как это делает настоящий плагин. Истёкший или ещё не вступивший в силу сертификат в диалоге выбора не появится.

Подписание заведомо невалидным сертификатом
---------------------------------------------

Если по сценарию нужен именно просроченный сертификат, он выбирается явно — тем же способом, что и в штатном режиме: вызывающая сторона передаёт отпечаток нужного
сертификата, и тогда фильтр по сроку не применяется. В режиме ``remote`` отпечатком выступает идентификатор сертификата в симуляторе.

Учтите при планировании проверок: на пути подписания из интерфейса платформа не вычисляет признаки ``isSignValid`` и ``isCertificateValid`` — они заполняются только для подписей,
полученных **от провайдера ЭДО**. Поэтому содержательная негативная проверка ставится с другой стороны: подпись создаётся действием симулятора с указанием просроченного
сертификата и приходит в Citeck штатным путём приёма документов.
