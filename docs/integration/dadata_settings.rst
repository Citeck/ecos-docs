DaData. Настройка и техническое описание
==========================================

Интеграция с сервисом `DaData <https://dadata.ru/>`__ заполняет реквизиты контрагента по ИНН. Пользователь вводит ИНН в карточке контрагента, нажимает **«Автозаполнение»** — и Citeck подставляет наименование, КПП, ОГРН, ОКПO и юридический адрес из ЕГРЮЛ.

Раздел для администраторов: как устроена интеграция с DaData, как подключить ключ, какие поля передаются, как диагностировать ошибки и какие ещё возможности DaData можно подключить. Возможности для пользователей описаны в разделе :ref:`dadata_info`.

   :depth: 2
   :local:

Состав интеграции
-----------------

Интеграция поставляется артефактами модуля справочников и выполняется микросервисом :ref:`ecos-integrations<ecos_integrations_app>`.

.. list-table::
   :header-rows: 1
   :widths: 30 25 45
   :class: tight-table

   * - Компонент
     - Тип
     - Назначение
   * - ``ecos-counterparty-form``
     - Форма
     - Форма типа ``ecos-counterparty``: кнопка **«Автозаполнение»**, сборка юридического адреса, диалог перезаписи заполненных полей
   * - ``findCounterpartyByInn``
     - Источник записей (``rest``)
     - Принимает ИНН, хранит API-ключ DaData в параметре ``token``
   * - ``counterparty-suggestions-dadata``
     - :ref:`Источник данных<data_sources>` (REST)
     - Отправляет запрос в DaData и преобразует ответ JOLT-спецификацией

Поток запроса
~~~~~~~~~~~~~

.. mermaid::

   sequenceDiagram
       actor U as Пользователь
       participant F as Форма контрагента
       participant R as Источник записей<br/>findCounterpartyByInn
       participant S as Источник данных<br/>counterparty-suggestions-dadata
       participant D as DaData
       U->>F: Кнопка «Автозаполнение»
       F->>F: Проверка: ИНН не пустой
       F->>R: Records.query(integrations/rs-findCounterpartyByInn, { inn })
       R->>S: inn, token (API-ключ DaData)
       S->>D: POST /suggestions/api/4_1/rs/findById/party<br/>Authorization: Token, { branch_type: MAIN, query: inn }
       D-->>S: Сведения из ЕГРЮЛ / ЕГРИП
       S->>S: JOLT (jsonRespTfmSpec): отбор реквизитов,<br/>адрес → legalAddress
       S-->>R: Реквизиты
       R-->>F: Реквизиты
       F->>F: Сборка строки юридического адреса
       F->>U: Перезаписать заполненные поля?
       U-->>F: Подтверждение
       F->>F: Заполнение полей карточки

Одно автозаполнение — один запрос к DaData. Метод ``findById/party`` с ``branch_type: MAIN`` ищет только головную организацию и одинаков на всех тарифах.

Подключение
-----------

Ключи DaData
~~~~~~~~~~~~

В личном кабинете DaData доступны два ключа:

.. list-table::
   :header-rows: 1
   :widths: 20 50 30
   :class: tight-table

   * - Ключ
     - Для чего нужен
     - Используется в Citeck
   * - API-ключ
     - Подсказки, поиск организации по ИНН, банка по БИК, адреса по коду, справочники — всё, что оплачивается подпиской
     - Да
   * - Секретный ключ
     - Передаётся в заголовке ``X-Secret``. Нужен для платных поштучных методов стандартизации (разбор адреса, проверка паспорта, ФИО, телефона, email), API статистики и баланса, MCP-сервера DaData
     - Нет

Для автозаполнения достаточно API-ключа. Секретный ключ в Citeck вписывать некуда: он понадобится, только если будут подключены стандартизация, мониторинг лимита или MCP-сервер.

DaData считает API-ключ публичным: для виджета подсказок он встраивается в код веб-страницы. Поэтому всё, что списывает деньги с баланса или показывает статистику аккаунта, дополнительно требует секретного ключа, а методы стандартизации DaData запрещает вызывать из браузера. Секретный ключ допустимо хранить только на сервере, в :ref:`секретах<ecos_secret>`.

Получение ключа
~~~~~~~~~~~~~~~

1. Перейдите на https://dadata.ru и нажмите кнопку **«Войти»** в правом верхнем углу экрана.

2. В открывшемся окне выберите **«Зарегистрироваться»**. Введите имя пользователя, электронную почту и пароль, затем нажмите кнопку регистрации.

3. Подтвердите email: на указанный адрес придёт письмо со ссылкой для подтверждения. Без этого шага ключи не будут сгенерированы.

4. Перейдите в личный кабинет по адресу https://dadata.ru/profile/ — в нижней части страницы указаны API-ключ и секретный ключ аккаунта.

5. Скопируйте **API-ключ**. Секретный ключ для автозаполнения не нужен.

Настройка Citeck
~~~~~~~~~~~~~~~~

1. Перейдите в рабочее пространство **«Раздел администратора»** → **Интеграция** → **Источники записей**.
2. Откройте запись **findCounterpartyByInn**.
3. Вставьте API-ключ в параметр ``token`` и сохраните запись.

     :width: 700
     :align: center

|

В поставке параметр ``token`` пустой — без ключа автозаполнение не работает.

.. warning::

   Ключ хранится в настройках источника записей открытым текстом, а не в секретах. Его видят все, у кого есть доступ к настройкам источников записей. Ограничьте этот доступ и не используйте для Citeck ключ аккаунта DaData, на котором подключены платные поштучные сервисы.

Почему ключ не в секрете
~~~~~~~~~~~~~~~~~~~~~~~~

Это ограничение платформы, а не только интеграции с DaData. Конфигурация REST-источника данных содержит только URL, признак Internal, HTTP-метод, заголовки, тело запроса и JOLT-спецификацию — поля для ссылки на секрет нет. Поэтому ключ передаётся параметром источника записей и подставляется в заголовок ``Authorization``. Тот же приём используется в REST-источнике данных для Jira.

Для сравнения, токен Контур.Фокуса хранится в секрете ``kontur-focus-api-token`` и подставляется через эндпоинт: вызов Контур.Фокуса реализован маршрутом Camel DSL, а не REST-источником данных.

Перенести ключ DaData в секрет можно двумя способами:

.. list-table::
   :header-rows: 1
   :widths: 40 30 30
   :class: tight-table

   * - Вариант
     - Что потребуется
     - Эффект
   * - Добавить в конфигурацию REST-источника данных ссылку на секрет
     - Доработка ``ecos-integrations`` и формы REST-источника данных
     - Секреты станут доступны всем REST-источникам, включая Jira
   * - Перенести вызов DaData в маршрут Camel DSL с эндпоинтом и секретом
     - Новый маршрут по образцу Контур.Фокуса, переделка источника записей
     - Решает задачу только для DaData

Известные ограничения
---------------------

.. list-table::
   :header-rows: 1
   :widths: 30 15 55
   :class: tight-table

   * - Ограничение
     - Где
     - Причина и последствие
   * - Руководитель не заполняется
     - Источник данных
     - JOLT пишет ``CEOname``, форма и модель ждут ``ceoName``. Если поле заполнено вручную, форма каждый раз спрашивает про перезапись: сравнивает значение с ``undefined``
   * - Юридический адрес без индекса
     - Форма
     - Индекс приходит в ``legalAddress.zipCode``, но в строку адреса не попадает
   * - Неверный порядок частей адреса
     - Источник данных и форма
     - Район города (``city_district``) положен в слот ``district``, который в строке стоит перед городом; район субъекта (``area``) не передаётся. Для региональных городов район встаёт перед городом, для сёл и посёлков пропадает муниципальный район
   * - Формат «сокращение + точка + значение»
     - Форма
     - «р-н. Печатники», «пр-кт. Волгоградский», «обл. Московская» вместо готовых полей DaData ``*_with_type``
   * - Статус компании не проверяется
     - Источник данных
     - ``data.state.status`` не передаётся — ликвидированная или банкротящаяся компания заполняется без предупреждения
   * - ИП не распознаются
     - Источник данных и форма
     - Не передаются ``data.type`` и ``data.fio``: не проставляется ``counterpartyKind``, не заполняются ``lastName``, ``firstName``, ``patronymicName``, ОГРНИП уходит в ``ogrn`` вместо ``psrnsp``
   * - ОПФ не заполняется
     - Источник данных
     - ``data.opf.code`` не передаётся. Справочник ``legal-form`` пока не содержит кодов ОКОПФ, поэтому сопоставить ОПФ по коду нельзя
   * - Формат ИНН не проверяется
     - Форма
     - Проверяется только, что ИНН не пустой. При опечатке уходит лишний запрос, пользователь видит «Data is empty»

Лимиты и ошибки
---------------

Все запросы к DaData идут с одного IP-адреса сервера ``ecos-integrations``, поэтому ограничения по частоте действуют на всю инсталляцию. При ручном автозаполнении их не достичь; заметными они становятся при пакетном обогащении базы или когда несколько инсталляций выходят в интернет через один IP.

.. list-table::
   :header-rows: 1
   :widths: 35 65
   :class: tight-table

   * - Ограничение
     - Значение
   * - Запросов в сутки
     - Зависит от тарифа — от 10 000 на бесплатном. Лимит общий на все сервисы подписки
   * - Частота запросов
     - 30 в секунду с одного IP-адреса, на всех тарифах. Для стандартизации — 20 в секунду
   * - Новые соединения
     - 60 в минуту с одного IP-адреса, на всех тарифах. При переиспользовании соединения запросов в минуту может быть больше
   * - Длина запроса
     - До 300 символов
   * - Индивидуальное повышение
     - Ограничения по частоте общие для всех и индивидуально не меняются
   * - Актуальность данных
     - Сведения ЕГРЮЛ отстают не более чем на 3 дня, адреса обновляются раз в неделю

При отказе DaData пользователь видит общее сообщение **«Error while requesting data»**. Код ответа можно увидеть в логах ``ecos-integrations``:

.. list-table::
   :header-rows: 1
   :widths: 15 40 45
   :class: tight-table

   * - Код ответа
     - Причина
     - Что делать
   * - 403
     - Исчерпан суточный лимит запросов
     - Дождаться 00:00 — сервисы подписки включатся снова. При регулярном превышении — перейти на старший тариф
   * - 429
     - Превышена частота запросов или число новых соединений
     - Прекратить запросы: доступ восстанавливается через 5 минут после того, как нарушение прекратится

Расширение набора полей
-----------------------

Ответ DaData на запрос по ИНН содержит больше данных, чем попадает в карточку: лишнее отбрасывает JOLT-спецификация (``jsonRespTfmSpec``) источника данных ``counterparty-suggestions-dadata``. Чтобы передать поле в карточку:

1. Добавьте поле в JOLT-спецификацию.
2. Если в модели ``ecos-counterparty`` нет подходящего атрибута — добавьте атрибут в модель и компонент в форму.
3. Если ключ после JOLT совпадает с ключом компонента формы, значение заполнится без правки скрипта формы. Иначе доработайте скрипт.

Данные, доступные только на платных тарифах, появятся в ответе DaData сразу после смены тарифа, но в карточку попадут только после этих доработок.

.. dropdown:: Пример расширенной JOLT-спецификации (уровень data)
   :color: secondary

   В примере исправлен регистр ``ceoName`` и добавлены тип, статус, ОПФ, ФИО ИП, основной ОКВЭД, идентификатор DaData, должность руководителя, готовая строка адреса и коды ФИАС и КЛАДР. Текущий маппинг ``address.data`` → ``legalAddress`` сохраните внутри блока ``address.data`` рядом с новыми полями.

   .. code-block:: json

      "data": {
        "kpp": "[&2].kpp",
        "okpo": "[&2].okpo",
        "ogrn": "[&2].ogrn",
        "type": "[&2].partyType",
        "okved": "[&2].okved",
        "hid": "[&2].dadataHid",
        "management": {
          "name": "[&3].ceoName",
          "post": "[&3].ceoPost"
        },
        "name": {
          "short_with_opf": "[&3].shortOrganizationName",
          "full_with_opf": "[&3].fullOrganizationName"
        },
        "fio": {
          "surname": "[&3].lastName",
          "name": "[&3].firstName",
          "patronymic": "[&3].patronymicName"
        },
        "opf": {
          "code": "[&3].opfCode"
        },
        "state": {
          "status": "[&3].partyStatus"
        },
        "address": {
          "unrestricted_value": "[&3].juridicalAddressFull",
          "data": {
            "fias_id": "[&4].juridicalAddressFiasId",
            "kladr_id": "[&4].juridicalAddressKladrId"
          }
        }
      }

   Ключи ``ceoName``, ``lastName``, ``firstName``, ``patronymicName`` совпадают с ключами компонентов формы и заполнятся без правки скрипта. Остальное требует правки скрипта формы:

   .. list-table::
      :header-rows: 1
      :widths: 25 75
      :class: tight-table

      * - Что
        - Как
      * - Юридический адрес
        - Если пришёл ``juridicalAddressFull`` — записать его в ``juridicalAddress``, сборку из ``legalAddress`` не выполнять
      * - Вид контрагента
        - ``partyType``: ``LEGAL`` → ``legalEntity``, ``INDIVIDUAL`` → ``individualEntrepreneur`` в ``counterpartyKind``
      * - ОГРНИП
        - При ``INDIVIDUAL`` переложить ``ogrn`` в ``psrnsp``
      * - ОПФ
        - Найти запись справочника ``legal-form`` по ``opfCode`` и проставить ``legalForm`` — после того как в справочник добавят коды ОКОПФ
      * - Статус
        - При ``partyStatus`` не ``ACTIVE`` — предупреждение до заполнения полей
      * - ИНН
        - Проверка ``^\d{10}$`` или ``^\d{12}$`` до запроса
      * - Ошибки
        - Для 403 и 429 — отдельные сообщения: «Исчерпан суточный лимит DaData» и «Слишком много запросов, повторите через 5 минут»
      * - Диалог перезаписи
        - Список атрибутов в ``isNeedAsk`` привести к ключам формы

Дополнительные сведения об организации
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

На любом тарифе, включая бесплатный, DaData уже возвращает в ответе на запрос по ИНН больше данных, чем попадает в карточку:

.. list-table::
   :header-rows: 1
   :widths: 35 65
   :class: tight-table

   * - Сведения
     - Применение
   * - Тип: юридическое лицо или ИП, ФИО предпринимателя
     - Заполнение вида контрагента, ФИО и ОГРНИП для ИП
   * - Организационно-правовая форма и код ОКОПФ
     - Заполнение ОПФ
   * - Статус: действующая, ликвидируется, ликвидирована, банкротство, реорганизация
     - Предупреждение при заполнении карточки нерабочей компании
   * - Даты регистрации, ликвидации и последних изменений
     - Возраст компании, дата сверки с ЕГРЮЛ
   * - Должность руководителя и дата вступления в должность
     - «В лице генерального директора…» в шаблонах документов, проверка полномочий подписанта
   * - Основной ОКВЭД
     - Отрасль клиента, сегментация в CRM
   * - Коды ОКАТО, ОКТМО, ОКОГУ, ОКФС, КПП крупнейшего налогоплательщика
     - Полный набор реквизитов
   * - Головная организация или филиал, число филиалов
     - Структура клиента
   * - Юридический адрес готовой строкой с индексом, коды ФИАС (ГАР) и КЛАДР, координаты, признак качества разбора
     - Корректный адрес без сборки по частям, связь с ФИАС, карта клиентов

Реквизиты банков, адреса и контакты
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

Отдельные запросы, доступные на любом тарифе. Для большинства из них в карточке контрагента уже есть поля.

.. list-table::
   :header-rows: 1
   :widths: 30 70
   :class: tight-table

   * - Возможность
     - Что даёт
   * - Банк по БИК, SWIFT или ИНН
     - Наименование, БИК, SWIFT, корреспондентский счёт, адрес и статус банка — одним запросом
   * - Подсказки по адресам
     - Ввод почтового и других адресов с кодами ФИАС (ГАР) и КЛАДР, индексом и координатами
   * - Подсказки по ФИО и электронной почте

   * - Компании Беларуси и Казахстана
     - Реквизиты контрагентов из ЕАЭС

Работа с ФИАС (ГАР) и КЛАДР
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

DaData даёт доступ к своей копии ФИАС (ГАР) и КЛАДР по API — это запросы к справочнику, а не выгрузка базы. Копия обновляется раз в неделю.

- **Подсказки по адресам** — поиск адреса по любой части, индексу, коду ФИАС или кадастровому номеру; коды ФИАС и КЛАДР на каждом уровне от региона до квартиры.
- **Адрес по коду** — по коду ФИАС (ГАР) до квартиры, по коду КЛАДР до улицы. Полезно, когда адрес приходит из внешней системы кодом.
- **Обратное геокодирование** — адрес по координатам.
- **Стандартизация адресов** — разбор адреса из строки по полям, индекс, координаты, часовой пояс, кадастровые номера. Предназначена для массовой чистки адресов при миграции и импорте; оплачивается поштучно.

Коды ФИАС домов и квартир иногда меняются, а поиск по коду работает только по актуальным, поэтому адрес стоит хранить строкой рядом с кодом.

Государственные справочники
~~~~~~~~~~~~~~~~~~~~~~~~~~~

Доступны на любом тарифе: ОКВЭД 2, ОКПД 2, ОКТМО, страны (ISO 3166), валюты (ISO 4217), налоговые инспекции, таможни, суды, станции метро, МКТУ, профессии и должности ОКПДТР, медицинские должности, марки автомобилей. Их можно использовать в формах модулей — например, ОКПД 2 для предмета договора, суды для претензионно-исковой работы.

Проверки данных
~~~~~~~~~~~~~~~

Оплачиваются поштучно с баланса DaData, первые 100 записей бесплатно.

.. list-table::
   :header-rows: 1
   :widths: 30 50
   :class: tight-table

   * - Проверка
     - Что делает
   * - ФИО
     - Разбирает ФИО на части, определяет пол, склоняет по падежам
   * - Паспорт
     - Проверяет формат и сверяет со справочником недействительных паспортов МВД. Справочник не обновляется с 21 июня 2023 года
   * - Телефон
     - Оператор с учётом переноса номера, страна, город, часовой пояс
   * - Электронная почта
     - Исправляет опечатки, выявляет одноразовые адреса
   * - Компания по электронной почте
     - Сведения об организации по корпоративному адресу


MCP-сервер для AI-агентов
~~~~~~~~~~~~~~~~~~~~~~~~~

DaData предоставляет `MCP-сервер <https://dadata.ru/mcp/>`_, через который AI-агент получает сведения о компаниях и адресах. Через него агент Citeck AI мог бы проверять контрагента и заполнять карточку прямо из диалога. Сведения о компаниях предоставляются по подписке, проверка адресов и поиск владельца домена оплачиваются поштучно.

Возможные направления развития
------------------------------

- **Исправление автозаполнения.** Заполнение руководителя, юридический адрес в виде готовой строки DaData с индексом, предупреждение о ликвидированных и банкротящихся компаниях, распознавание ИП с заполнением ФИО и ОГРНИП, заполнение организационно-правовой формы, проверка формата ИНН, отдельные сообщения об исчерпании лимита.
- **Хранение ключа в секретах.** Поддержка секретов в REST-источниках данных — это же нужно для подключения стандартизации и мониторинга лимита.
- **Дополнительные сведения на бесплатном тарифе.** Должность руководителя, даты регистрации и ликвидации, основной ОКВЭД, коды статистики, коды ФИАС и КЛАДР юридического адреса.
- **Автозаполнение банка по БИК.** Наименование банка, БИК и SWIFT по одному запросу.
- **Ввод адресов с подсказками.** Почтовый и другие адреса с кодами ФИАС (ГАР), индексом и координатами.
- **Государственные справочники** — по потребностям модулей.
- **Мониторинг лимита** через API статистики DaData с предупреждением администратору до отказа.
- **MCP-сервер DaData** для агентов Citeck AI.
