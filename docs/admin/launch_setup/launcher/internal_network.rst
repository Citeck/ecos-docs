Запуск в закрытом контуре
============================

Для развёртывания без доступа к интернету подготовьте дистрибутив Launcher, определения workspace и бандлов, Docker-образы и, при необходимости, архивы данных. Перенос только Docker-образов не обеспечивает запуск на чистом хосте: Launcher также нужны конфигурация и сведения о выбранном релизе.

.. important::

    Архитектура образов должна соответствовать целевому хосту. В описанном ниже сценарии используйте хосты с одинаковой архитектурой процессора. Версии Launcher, бандла, конфигурации и образов должны соответствовать друг другу.

Подготовка на хосте с интернетом
---------------------------------

#. Скачайте пакет **citeck-desktop** для ОС и архитектуры целевого хоста. Подготовьте установщик Docker и его зависимости, если Docker ещё не установлен в закрытом контуре.
#. Подготовьте ZIP с конфигурацией workspace и определениями выбранной версии бандла. В архиве должны быть файл конфигурации, например ``workspace-v1.yml`` или ``workspace-v2.yml``, используемые им ресурсы и каталоги бандлов. Если бандлы находятся в отдельных Git-репозиториях, добавьте их содержимое в каталоги, заданные параметром ``path`` соответствующих репозиториев в workspace. Один ZIP только с workspace без внешних бандлов недостаточен.
#. Если нужны демонстрационные данные, скачайте соответствующий ZIP-снэпшот и сохраните его имя, идентификатор и контрольную сумму из workspace. Для переноса существующих данных подготовьте :ref:`снэпшот с секретами <launcher_snapshot_transfer>`.
#. Запустите выбранный бандл на подготовительном хосте и дождитесь загрузки всех образов. Учтите приложения, которые будут включены на целевом хосте, в том числе выбранный провайдер S3.
#. Загрузите служебный образ для операций с томами. По умолчанию используется:

   .. code-block:: shell

       docker pull registry.citeck.ru/community/launcher-utils:1.0

   Если задана переменная ``CITECK_UTILS_IMAGE``, подготовьте указанный в ней образ вместо стандартного.

#. Сохраните образы в tar-архив. Замените примеры имён на полный список образов выбранного бандла с точными тегами:

   .. code-block:: shell

       docker save -o citeck-bundle.tar image-a:X.Y image-b:X.Y registry.citeck.ru/community/launcher-utils:1.0

#. Перенесите установщики, конфигурацию, архивы образов и необходимые снэпшоты в закрытый контур.

Подготовка на целевом хосте
-----------------------------

#. Установите и запустите Docker, установите Launcher.
#. Загрузите Docker-образы:

   .. code-block:: shell

       docker load -i citeck-bundle.tar

#. Подготовьте workspace в Launcher. Откройте директорию Launcher через интерфейс или меню трея и определите каталог нужного workspace: ``ws/<workspaceId>/``. Завершите Launcher через **Выйти** перед изменением файлов.
#. Распакуйте подготовленный комплект конфигурации в ``ws/<workspaceId>/repo/``. Файл ``workspace-v1.yml`` или ``workspace-v2.yml`` должен лежать непосредственно в ``repo/``, без дополнительного каталога архива. В локальном комплекте не должно быть каталога ``.git``: такой ``repo/`` используется как офлайн-источник. Проверьте, что каталоги бандлов расположены по путям ``path`` из конфигурации workspace и содержат выбранный релиз.
#. Для workspace-снэпшота разместите скачанный ZIP в ``ws/<workspaceId>/snapshots/<snapshotId>.zip``. Файл должен соответствовать контрольной сумме из workspace. Пользовательский снэпшот существующей установки восстанавливайте через :ref:`импорт снэпшота <launcher_snapshot_transfer>`.

.. note::

    В desktop-режиме директория Launcher по умолчанию расположена в ``%LOCALAPPDATA%\Citeck\launcher`` на Windows, ``~/Library/Application Support/Citeck/launcher`` на macOS и ``~/.citeck/launcher`` на Linux. Переменная ``CITECK_HOME`` переопределяет этот путь. Для Linux-сервера используйте отдельный :ref:`серверный режим <launcher_server>`; CLI поддерживает импорт конфигурации при установке командой ``citeck install --workspace /path/workspace.zip --offline``. Это команда серверной установки, а не настройка GUI.

Запуск и проверка
-------------------

#. Запустите Launcher, выберите подготовленный workspace и убедитесь, что нужная версия бандла доступна без обращения к Git-серверу. Если Launcher предлагает загрузить отсутствующий репозиторий, дополните локальный комплект конфигурации.
#. Создайте :ref:`namespace <launcher_new_space>` с выбранным бандлом. При необходимости выберите заранее подготовленный workspace-снэпшот либо восстановите пользовательский снэпшот в остановленный namespace.
#. Нажмите **Обновить и запустить**. Не используйте принудительное обновление Git-репозиториев для офлайн-комплекта. Если требуется скачивание образа, подготовьте и перенесите недостающий образ с точным тегом.
#. При отключённой внешней сети дождитесь готовности всех необходимых приложений, откройте Citeck из Launcher и проверьте вход, чтение и сохранение документов. Убедитесь, что выбранные интеграции используют сервисы, доступные внутри закрытого контура.
