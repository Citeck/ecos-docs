Рабочие пространства
------------------------------------------

В лаунчере доступно создание нескольких рабочих пространств. Например, одно пространство можно использовать для запуска релизных версий, второе — для внутренних сборок разработки.

Рабочее пространство — это Git-репозиторий, из которого лаунчер читает бандлы, приложения и шаблоны namespace.

Для перехода к списку пространств нажмите **Рабочее пространство: <имя>** в левом верхнем углу стартового экрана:

.. image:: _static/ws_1.png
    :width: 600
    :align: center


Создание нового
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

Нажмите **Создать рабочее пространство...**:

.. image:: _static/ws_2.png
    :width: 600
    :align: center

Введите параметры:

.. list-table::
   :header-rows: 1
   :class: tight-table

   * - Параметр
     - Описание
   * - **Имя**
     - Имя пространства.
   * - **URL репозитория**
     - URL адрес Git-репозитория.
   * - **Ветка**
     - Ветка репозитория.
   * - **Период обновления**
     - Как часто лаунчер загружает изменения репозитория, в формате ISO 8601 (например, ``PT2H`` — раз в 2 часа).
   * - **Аутентификация**
     - **Нет (публичный репозиторий)** или **Токен (приватный репозиторий)**.

.. image:: _static/ws_3.png
    :width: 400
    :align: center

Для типа аутентификации **Токен** выберите в поле **Секрет с токеном** сохранённый :ref:`секрет <launcher_secrets>` или создайте новый (**Добавить новый…**): укажите название секрета и `персональный access-токен GitHub <https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/creating-a-personal-access-token>`_. Если мастер-пароль ещё не задан, лаунчер предложит его создать.

.. note::

    Чтобы создать токен, перейдите в **GitHub → аватар (слева) → Settings → Developer settings → Personal access tokens**, создайте новый токен и скопируйте его значение.

Введите токен в соответствующее поле и подтвердите:

.. grid:: 2
    :gutter: 2

    .. grid-item::

        .. image:: _static/ws_4.png
            :width: 350
            :align: center

    .. grid-item::

        .. image:: _static/ws_4_1.png
            :width: 350
            :align: center

Нажмите **Сохранить** — рабочее пространство будет создано.

Если токен не подошёл или истёк, при загрузке репозитория лаунчер покажет окно **Не удалось спулить Git репозиторий** с кнопками **Изменить токен** и **Выбрать другой**. Если репозиторий уже был загружен ранее, загрузку можно пропустить и повторить позже.

Выбор из созданных
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

.. image:: _static/ws_5.png
    :width: 600
    :align: center

Из списка пространство можно отредактировать (значок карандаша) или удалить. Настройки текущего пространства также открываются кнопкой **Настройки рабочей области** (шестерёнка рядом со списком), пунктом **Настройки рабочей области...** в списке и на странице :ref:`Настройки <launcher_settings>`. Внутри пространства доступен запуск уже настроенного namespace и создание нового:

.. image:: _static/ws_6.png
    :width: 600
    :align: center

.. warning::

    Текущее рабочее пространство удалить нельзя — сначала переключитесь на другое. При удалении рабочего пространства удаляются его конфигурация, кэш репозитория и все его namespace вместе с их данными (томами).

Конфигурация рабочего пространства
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

Пункт **Редактировать workspace-v1.yml...** открывает конфигурацию рабочего пространства: репозитории бандлов и образов, шаблоны namespace, варианты быстрого старта, снэпшоты, дополнительные сервисы и секреты. Правки сохраняются как наложение поверх версии из Git и применяются заново при каждой синхронизации. Кнопка **Сбросить к git** отменяет правки.

Кнопка **Принудительное обновление** рядом со списком пространств сразу загружает изменения репозитория, не дожидаясь периода обновления.
