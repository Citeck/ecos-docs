Работа с секретами и мастер-паролем
--------------------------------------------------------------------

.. contents::

**Секреты** — учётные данные, которые лаунчер хранит для доступа к внешним ресурсам: токены Git-репозиториев рабочих пространств и логины/пароли приватных Docker-реестров (например, для загрузки образов Enterprise версии).

**Мастер-пароль** шифрует все секреты, используемые в лаунчере. Пока в лаунчере нет ни одного секрета, мастер-пароль не нужен: он задаётся при добавлении первого секрета. После этого его потребуется вводить один раз при каждом запуске лаунчера — в окне **Разблокировка секретов**.

.. image:: _static/restart_secret.png
    :width: 600
    :align: center

Пока секреты не разблокированы, лаунчер не запускает namespace, которому они нужны — например, если его образы загружаются из приватного реестра. Запуск продолжится автоматически после ввода мастер-пароля.

Сброс мастер-пароля
~~~~~~~~~~~~~~~~~~~
.. note::

  Мастер-пароль не может быть восстановлен. Его можно только сбросить, что приведёт к удалению всех секретов.

Установка мастер-пароля
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

При установке, например, Enterprise версии для скачивания закрытых образов необходимо ввести учетные данные и задать мастер-пароль, который будет использоваться для шифрования секретов. Если мастер-пароль не установлен, лаунчер предложит его создать.

Введите и подтвердите мастер-пароль. Если пароли не совпадают, под полем появится сообщение **Пароли не совпадают**:

.. image:: _static/secret_1.png
    :width: 400
    :align: center

Просмотр, создание и удаление секретов
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

Для перехода к управлению секретами нажмите:

.. image:: _static/secret_0.png
    :width: 600
    :align: center

Откроется список секретов с возможностью создания, проверки, изменения и удаления каждого из них. Для каждого секрета указаны имя, хост и тип:

- **Токен** — токен доступа к Git-репозиторию;
- **Basic (логин/пароль)** — логин и пароль;
- **Basic (логин/пароль) — реестр** — учётные данные Docker-реестра.

Секреты рабочего пространства
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

Конфигурация рабочего пространства может объявлять собственные секреты — например, пароль базы данных сервиса **observer**. Значение в конфигурации — значение по умолчанию: при первом использовании каждый namespace сохраняет свою копию и дальше использует её, даже если значение в конфигурации изменится. Такие секреты не отображаются в списке секретов и не требуют мастер-пароля; если мастер-пароль задан, они хранятся зашифрованными вместе с остальными.

Переход с лаунчера 1.x
~~~~~~~~~~~~~~~~~~~~~~

При первом запуске после обновления с версии 1.x лаунчер переносит рабочие пространства, namespace и секреты. Если секреты были зашифрованы, лаунчер сначала попросит ввести прежний мастер-пароль (окно **Введите мастер-пароль**) и только после этого запустит namespace. Исходная база 1.x не изменяется и сохраняется в файле ``storage.db.kotlin-bak`` в директории лаунчера.
