.. image:: _static/namespaces.png
    :width: 600
    :align: center

После успешного запуска отображается рабочее пространство **(1)** и список доступных в нем namespace **(4)**:

.. image:: _static/namespaces_1.png
    :width: 600
    :align: center

- **(1)** - выбор и создание :ref:`рабочего пространства <launcher_workspace>`. В выпадающем списке также доступны пункты **Настройки рабочей области...** и **Редактировать workspace-v1.yml...**
- **(2)** - принудительное обновление рабочего пространства (загрузка изменений из его Git-репозитория)
- **(3)** - настройки рабочего пространства: имя, URL и ветка репозитория, период обновления, аутентификация

Конфигурацию рабочего пространства (файл **workspace-v1.yml**) можно отредактировать через пункт **Редактировать workspace-v1.yml...**. Изменения сохраняются как наложение поверх версии из Git и применяются заново при каждой синхронизации; кнопка **Сбросить к git** отменяет их:

.. image:: _static/ws_config.png
    :width: 600
    :align: center

- **(4)** - список namespace выбранного рабочего пространства
- **(5)** - выбор языка интерфейса
- **(6)** - выбор светлой/темной темы интерфейса

Справа в верхней панели также расположены:

- **Обновление лаунчера** — значок загрузки. Зелёная точка на нём означает, что доступна новая версия, красная — что последнее обновление не установилось. См. :ref:`Автообновление лаунчера <launcher_self_update>`.
- **Настройки** (шестерёнка) — страница глобальных настроек, см. :ref:`Страница настроек <launcher_settings>`.

Микросервисы и приложения
---------------------------

1. **Запускаемые микросервисы и приложения**: микросервисы ядра, приложения Citeck, сторонние — с указанием статуса и потребляемых ресурсов CPU и оперативной памяти. Клик по строке открывает панель с подробной информацией о контейнере (образ, порты, тома, переменные окружения). Доступные действия:

   - **1a** — остановить/запустить. Правый клик по кнопке — перезапуск. Остановленное вручную приложение остаётся остановленным и после перезапуска лаунчера, пока вы не запустите его снова. Запустить отдельное приложение можно только в запущенном namespace;
   - **1b** — лог микросервиса;
   - **1c** — ручная настройка микросервиса/приложения:

   **Левый клик** — редактировать конфигурацию Docker-приложения (YAML):

   .. image:: _static/setting_left.png
       :width: 600
       :align: center

   **Правый клик** — редактировать файлы томов:

   .. image:: _static/setting_right.png
       :width: 600
       :align: center

   **Синий маркер** означает, что у приложения есть ручная конфигурация, которая не управляется лаунчером. Чтобы сбросить ручные изменения, откройте редактор и нажмите **«Сбросить»**.

   Сохранённая конфигурация применяется сразу: пересоздаются только те контейнеры, чья конфигурация действительно изменилась. Смена версии образа через редактор тоже применяется сразу. Изменить версию сторонней зависимости (PostgreSQL, RabbitMQ и т. п.) на несовместимую с её данными таким способом нельзя — для этого используется :ref:`миграция зависимостей <launcher_dependencies>`.

   Статус **Ожидание** означает, что приложение ждёт запуска своих зависимостей; рядом со статусом указано, каких именно (**Ожидает: …**). Если зависимость остановлена, запустите её — ожидающее приложение продолжит запуск само.

2. **Обновить и запустить** все микросервисы и приложения. При клике правой кнопкой мыши доступно действие **Принудительно обновить и запустить** — принудительное обновление данных из git-репозиториев с конфигурацией рабочего пространства и бандлов (китов), без учёта периода обновления:

   .. image:: _static/force_update.png
       :width: 350
       :align: center

   **Обновить и запустить** загружает изменения репозиториев рабочего пространства и бандлов, обновляет образы с тегом ``snapshot`` и пересоздаёт только те сервисы, у которых изменились конфигурация или образ. Пока обновление готовится, на кнопке отображается индикатор; если обновление не удалось, лаунчер покажет причину.

3. **Остановка** всех микросервисов и приложений.

Статус и ресурсы
---------------------------

4. Актуальный **статус** процесса разворачивания. Статус **Зависло** означает, что запуск не может завершиться сам: например, приложение завершилось с ошибкой или ждёт остановленную зависимость. Запустите нужное приложение — namespace вернётся в статус **Работает**.

5. Общие **потребляемые ресурсы CPU/RAM**.

Над списком приложений при необходимости выводятся сообщения:

- **Нужны учётные данные реестра для: …** — для загрузки образов нужны учётные данные, кнопка **Указать креды** открывает окно их выбора;
- **Доступно обновление зависимости: …** — см. :ref:`Обновление зависимостей <launcher_dependencies>`;
- **В этом неймспейсе нет сервисов Citeck** — бандл не удалось загрузить или он не содержит приложений; запустится только стороннее окружение. Проверьте репозиторий и версию бандла в настройках namespace;
- **Мало места на диске** — на диске, где лаунчер хранит данные, заканчивается свободное место.

Доступ и сопутствующие сервисы
---------------------------------

6. **Открыть Citeck в браузере** (только при статусе **Работает**).

7. Доступ к **сопутствующим сервисам** — открываются в браузере в отдельной вкладке:

   - **Keycloak Admin** — интерфейс управления Keycloak (система управления идентификацией и авторизацией). Отображается, если при настройке пространства имён выбран тип авторизации Keycloak. **Логин / пароль:** ``admin / admin``
   - **Spring Boot Admin** — :ref:`интерфейс <spring_boot_admin>` для мониторинга и администрирования Spring Boot-приложений: просмотр состояния, метрик, логов и управление приложениями.
   - **PG Admin** — интерфейс для администрирования и управления базами данных PostgreSQL (http://localhost:5050). **Логин / пароль:** ``admin@admin.com / admin``. **Пароль для БД:** ``postgres``
   - **Mailpit** — инструмент для тестирования и отладки электронной почты во время разработки: перехватывает письма и отображает их в веб-интерфейсе без реальной отправки (http://localhost:8025).
   - **RabbitMQ** — интерфейс брокера сообщений (message broker), который обеспечивает асинхронный обмен данными между компонентами распределённых систем (http://127.0.0.1:15672). **Логин / пароль:** ``admin / admin``

   Ссылки на PG Admin, Mailpit и RabbitMQ всегда ведут на этот компьютер (localhost / 127.0.0.1): эти сервисы доступны только локально.

   Если в конфигурации рабочего пространства заданы собственные ссылки, они выводятся в конце списка.

8. Документация по платформе Citeck:

   - **Documentation** — переход на `ресурс <https://citeck-ecos.readthedocs.io/ru/latest/index.html>`_, содержащий документацию по платформе.
   - **AI Documentation Bot** — переход в `Telegram-бот <https://t.me/haski_citeck_bot>`_.

.. _launcher_ports:

Порты и доступ из сети
~~~~~~~~~~~~~~~~~~~~~~

Порты контейнеров, для которых не указан адрес, публикуются только на адресе **127.0.0.1**: Citeck, базы данных и интерфейсы сервисов доступны только с этого компьютера. Прокси (адрес Citeck) публикуется на всех сетевых интерфейсах, только если хост namespace не локальный.

Чтобы открыть порт в сеть, укажите адрес явно в конфигурации приложения (**1c**, левый клик), в секции ``ports``:

.. code-block:: yaml

    ports:
      - '*:15432:5432'          # все сетевые интерфейсы
      - '192.168.1.10:8080:80'  # конкретный адрес

Значение со звёздочкой обязательно заключайте в кавычки — иначе YAML не примет запись. Новая привязка вступает в силу, когда контейнер пересоздаётся; уже запущенный контейнер сохраняет прежнюю.

.. note::

    Правка ``ports`` прокси, сохранённая в версии лаунчера до 2.15.2, не содержит адреса и теперь тоже означает 127.0.0.1. Если прокси должен быть доступен из сети, проверьте его конфигурацию.

Инструменты лаунчера
---------------------------

9. **Открыть каталог namespace** в файловом менеджере. В нём находятся, в частности, каталог ``snapshots`` со :ref:`снэпшотами <launcher_dump>` и каталог ``export/<приложение>``, куда веб-приложения Citeck сохраняют сжатый дамп памяти при ошибке ``OutOfMemoryError`` (хранится только самый свежий дамп).

10. Открыть **логи лаунчера**:

    .. image:: _static/log.png
        :width: 800
        :align: center

    Данные лога можно отфильтровать по типу **(1)**, в нём доступен поиск **(2)**, а также возможность скопировать, очистить или выгрузить лог **(3)**.

11. **Тома**, которые используются. Можно вычислить их размер, удалить том или все тома (только при остановленном namespace) или перейти к :ref:`снэпшотам данных <launcher_dump>`:

    .. image:: _static/volumes.png
        :width: 500
        :align: center

Рядом с кнопкой томов расположена кнопка **Зависимости** — версии сторонних компонентов (PostgreSQL, RabbitMQ, ZooKeeper и др.), их миграция и откат. См. :ref:`Обновление зависимостей <launcher_dependencies>`.

    .. image:: _static/secrets.png
        :width: 500
        :align: center

    См. подробно о работе с :ref:`секретами <launcher_secrets>`.

13. **Дамп системы** — сохраняет архив с информацией о системе, конфигурацией, логами лаунчера и отчётами о миграциях зависимостей и открывает папку с ним. Пароли и другие секреты в архиве маскируются. Этот архив стоит приложить к обращению в поддержку.

14. **Настройки пространства имён**. См. подробно о настройках :ref:`пространства имён (namespace) <launcher_new_space>`. Точка на шестерёнке означает, что в репозитории есть более новый бандл: зелёная — его можно выбрать сразу, жёлтая — для него сначала нужно обновить лаунчер. Подробности — во всплывающей подсказке.

Страница настроек
~~~~~~~~~~~~~~~~~

Шестерёнка **Настройки** в правом верхнем углу открывает страницу глобальных настроек. Она доступна всегда — и на стартовом экране, и при открытом namespace:

- **Состояние системы** — результат проверок лаунчера (например, доступности Docker).
- **Рабочая область** — параметры Git-репозитория текущего :ref:`рабочего пространства <launcher_workspace>`, кнопки **Настройки рабочей области...** и **Редактировать workspace-v1.yml...**.
- **Учётные данные реестров** — какие сохранённые учётные данные лаунчер использует для загрузки образов из приватных Docker-реестров. Каждый хост реестра привязан к одному секрету. Кнопка **Настроить** позволяет выбрать другие учётные данные или удалить привязку (**Удалить привязку**). Секрет, созданный для другого хоста, помечается предупреждением.

Действия в трее
----------------

.. image:: _static/tray_actions.png
    :width: 200
    :align: center

- Открыть
- **Экспорт** информации о системе (дамп системы)
- Переход в **директорию лаунчера** (папка с логами, данными конфигурации, рабочими пространствами)
- DevTools
- Выйти

.. note::

    При закрытии лаунчера запущенные контейнеры продолжают работать. Чтобы освободить ресурсы, перед выходом остановите namespace кнопкой **Остановить**.
