Создание нового пространства имён
-----------------------------------

Для запуска другого комплекта поставки создайте новый namespace — нажмите **Создать новый namespace**:

.. image:: _static/new_namespace.png
    :width: 600
    :align: center

Укажите параметры нового пространства имён:

.. list-table::
   :header-rows: 1
   :class: tight-table

   * - Параметр
     - Описание
   * - **Имя**
     - Имя namespace.
   * - **Репозиторий бандлов**
     - Enterprise или community. Список берётся из конфигурации рабочего пространства — репозитории добавляются и меняются в её настройках.
   * - **Бандл**
     - Версия поставки. **LATEST** — самая новая версия, которую может запустить текущий лаунчер. Кнопка рядом с полем обновляет список бандлов из репозитория.
   * - **Снэпшот**
     - Снэпшот данных (при необходимости). Доступен только при создании namespace.
   * - **Тип аутентификации**
     - **KEYCLOAK** или **BASIC**. Для **BASIC** в поле **Пользователи Basic Auth** перечислите пользователей через запятую.
   * - **Включить HTTPS (самоподписанный)**
     - Прокси отдаёт Citeck по HTTPS с автоматически сгенерированным сертификатом. Порт следует за схемой автоматически — 443 для HTTPS, 80 для HTTP, — поэтому включение и выключение HTTPS не требует других настроек. При первом входе браузер покажет предупреждение о самоподписанном сертификате.

.. image:: _static/new_namespace_1.png
    :width: 400
    :align: center

Нажмите **Создать**.

.. note::

    Namespace нельзя создать без бандла или на версии бандла, которой нет в репозитории. Если выбранный бандл требует более новую версию лаунчера, создание будет отклонено с указанием версии, до которой нужно :ref:`обновить лаунчер <launcher_self_update>`.

Если выбран снэпшот данных, дождитесь его загрузки и проверки. Для запуска нажмите **Обновить и запустить**:

.. image:: _static/new_namespace_2.png
    :width: 700
    :align: center

Для загрузки образов Enterprise версии необходимы учетные данные. Выберите существующие или добавьте новые:

.. image:: _static/harbor_1.png
    :width: 400
    :align: center

Введите мастер-пароль или установите его, если он ещё не задан:

.. image:: _static/new_namespace_2_1.png
    :width: 400
    :align: center

Введите пароль для скачивания закрытых образов:

.. image:: _static/harbor_2.png
    :width: 400
    :align: center

Выбранные учётные данные запоминаются для хоста реестра. Изменить или удалить эту привязку можно на странице :ref:`Настройки <launcher_settings>` → **Учётные данные реестров**.

Изменение namespace
~~~~~~~~~~~~~~~~~~~

Параметры namespace можно изменить позже — шестерёнкой рядом с его названием или через список namespace (**Изменить**). Изменения активного namespace применяются сразу после сохранения: пересоздаются только затронутые контейнеры.

На вкладке **Дополнительно** для namespace, созданных старыми версиями лаунчера, доступен флажок **Включить MongoDB**.

.. warning::

    При удалении namespace удаляются не только его конфигурация, но и его данные: тома и каталог namespace, включая сохранённые в нём снэпшоты. Если снэпшоты нужны, скопируйте их заранее.

MongoDB
~~~~~~~

Новые namespace создаются без MongoDB: данные процессов ecos-process хранятся в PostgreSQL, начиная с ecos-process 2.33.0. Если выбранный бандл содержит более старую версию ecos-process, MongoDB включается автоматически.

В существующих namespace MongoDB остаётся включённой. Отключить её можно флажком **Включить MongoDB** на вкладке **Дополнительно**:

- нужен ecos-process 2.33.0 или новее;
- если в namespace уже есть процессы, оставьте MongoDB включённой, пока ecos-process не сообщит о завершении миграции данных, — иначе он не запустится.

При отключении удаляется только контейнер MongoDB, том с её данными сохраняется.

.. _launcher_detached_apps:

Какие приложения запускаются
~~~~~~~~~~~~~~~~~~~~~~~~~~~~

Состав приложений namespace определяет бандл. Часть приложений шаблон рабочего пространства помечает как необязательные — они создаются в статусе **Остановлен** и не запускаются сами. В рабочем пространстве по умолчанию это, например, **observer** и **observer-postgres**, а также **rag**, **qdrant** и **stt-sidecar** (есть только в Enterprise-бандлах).

- Чтобы включить такое приложение, нажмите кнопку запуска в его строке. После этого оно запускается вместе с namespace.
- Приложение, которое впервые появилось в namespace с новой версией бандла и помечено в шаблоне как необязательное, тоже появится остановленным. Уже запускавшиеся приложения это правило не затрагивает.
- Приложение, остановленное вручную, остаётся остановленным и после перезапуска лаунчера.

Если приложению нужна остановленная зависимость, оно ждёт её в статусе **Ожидание**, а namespace показывает статус **Зависло**. Запустите зависимость — ожидающее приложение продолжит запуск само.

.. note::

    **Observer** — сервис наблюдаемости стенда: приём логов и телеметрии, мониторинг RabbitMQ, PostgreSQL и ZooKeeper. Он появляется в namespace, если его образ есть в бандле, а сервис и его база объявлены в конфигурации рабочего пространства (в официальных рабочих пространствах объявлены). После запуска встроенный интерфейс observer доступен на этом компьютере на порту 17016.
