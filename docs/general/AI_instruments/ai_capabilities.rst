.. _ai-capabilities:

Возможности AI в платформе: вопросы и ответы
=============================================

.. contents::
    :depth: 2

Раздел отвечает на типовые вопросы о возможностях AI в Citeck. Каждый ответ — краткая сводка со ссылкой на раздел документации с подробностями.

Агенты и модели
----------------

.. dropdown:: Есть ли готовые AI-агенты от вендора?
    :color: secondary

    Вместе с платформой поставляются агенты: помощник по задачам и документам, агент конфигурации платформы, помощник по изображениям, помощник по возможностям платформы, аудитор конфигурации, оператор публикации. Функциональность активно развивается: с новыми релизами появляются новые преднастроенные агенты, а в будущем планируется отдельный маркетплейс агентов. См. :ref:`Преднастроенные агенты <preconfigured-agents>`.

.. dropdown:: Можно ли создать собственного агента?
    :color: secondary

    Агент — обычная запись платформы: системный промпт, белый список инструментов, провайдер и модель. Создаётся через журнал **AI Агенты** без программирования; разработчик может добавить собственный инструмент, реализовав интерфейс ``CiteckAiTool``. См. :ref:`Пользовательские AI-агенты <user-agents>`.

.. dropdown:: Настраиваются ли агенты визуально, без кода?
    :color: secondary

    Параметры агента — название, инструкция, провайдер, модель, инструменты, температура — задаются полями формы в журнале администратора. См. :ref:`Создание агента <agent-creation>`.

.. dropdown:: Поддерживаются ли различные внешние LLM?
    :color: secondary

    Через Spring AI поддерживаются OpenAI, Anthropic, DeepSeek, Ollama и другие OpenAI-совместимые провайдеры, включая локальные модели. См. :ref:`Провайдеры LLM <AI_assistant_config>`.

.. dropdown:: Могут ли разные агенты работать на разных LLM?
    :color: secondary

    Провайдер и модель — реквизиты записи агента; модель агента применяется и в генераторах артефактов. См. :ref:`Модели AI-агентов <ai-agent-models>`.

.. dropdown:: Можно ли ставить задачи обычным человеческим языком?
    :color: secondary

    Все взаимодействие с ассистентом — естественным языком, включая создание приложений, поиск записей и генерацию документов. См. :ref:`AI ассистент <AI_assistant>`.

.. dropdown:: Можно ли загрузить техническое задание?
    :color: secondary

    При генерации бизнес-приложения вместо ответов на уточняющие вопросы можно приложить файл спецификации; произвольные файлы анализируются в чате. См. разделы «Генерация бизнес-приложений» и «Работа с файлами в чате» в :ref:`описании ассистента <AI_assistant>`.

Совместная работа агентов
--------------------------

.. dropdown:: Есть ли агентный конвейер?
    :color: secondary

    Многоартефактные запросы выполняются конвейером «план → утверждение человеком → исполнение по графу зависимостей» с восстановлением после ошибок и пересмотром плана. См. :ref:`Агентный конвейер <ai-pipeline>`.

.. dropdown:: Есть ли оркестрация агентов?
    :color: secondary

    Единая точка входа маршрутизирует запросы по движкам агентов; структурные решения принимает код платформы, модель отвечает за содержание. См. :ref:`Архитектуру выполнения <ai-architecture>`.

.. dropdown:: Есть ли разделение труда между агентами (менеджер, разработчик, аналитик, дизайнер, архитектор)?
    :color: secondary

    Роли распределены между этапами конвейера и специализированными инструментами: планирование (план приложения со структурой), генерация скриптов, процессов, форм и типов данных. См. :ref:`Агентный конвейер <ai-pipeline>` и :ref:`каталог инструментов <agent-tools-catalog>`.

.. dropdown:: Есть ли агент-тестировщик?
    :color: secondary

    Каждый артефакт проходит структурную валидацию до публикации; аудитор конфигурации проверяет приложение по чек-листу безопасности и качества с отчётом по уровням риска (доступен с релиза 2026.3). См. :ref:`Преднастроенные агенты <preconfigured-agents>`.

.. dropdown:: Есть ли агент-оператор, принимающий решение о развёртывании?
    :color: secondary

    Оператор публикации валидирует артефакт, оценивает влияние и выносит решение «публиковать / вернуть на доработку»; публикация — только после подтверждения человеком, с контролем области (доступен с релиза 2026.3). См. :ref:`Преднастроенные агенты <preconfigured-agents>` и :ref:`область публикации <ai-deploy-scope>`.

.. dropdown:: Может ли быть несколько агентов одной роли?
    :color: secondary

    Количество записей агентов не ограничено; агенты одной специализации могут отличаться моделями, инструкциями и наборами инструментов. См. :ref:`Пользовательские AI-агенты <user-agents>`.

.. dropdown:: Работают ли агенты параллельно?
    :color: secondary

    Диалоги и автономные вызовы разных агентов выполняются независимо и одновременно; этапы одного плана исполняются последовательно по графу зависимостей. См. :ref:`Агентный конвейер <ai-pipeline>`.

.. dropdown:: Есть ли у каждого агента собственный контекст?
    :color: secondary

    У агента — своя инструкция, белый список инструментов и память диалога; каждый этап конвейера работает в изолированной памяти. См. :ref:`Архитектуру выполнения <ai-architecture>`.

Управление и контроль
----------------------

.. dropdown:: Можно ли подключить базу знаний (RAG) каждому агенту?
    :color: secondary

    База знаний подключается через инструменты в белом списке агента; источники — записи рабочих пространств и Git-репозитории; результаты фильтруются по правам. См. :ref:`Подключение базы знаний агенту <agent-knowledge-base>` и :ref:`настройку RAG <rag-config>`.

.. dropdown:: Как контролируется расход токенов по агенту?
    :color: secondary

    Каждый вызов LLM сохраняется записью в журнале **«Вызовы LLM»** административного раздела AI с привязкой к агенту (есть преднастройка группировки по агентам); фиксируются токены запроса, ответа, рассуждений и кэша, длительность и причина завершения. Выполнение дополнительно ограничено бюджетами (вызовы инструментов, этапы, время). См. :ref:`Телеметрия и расход токенов <ai-telemetry>` и :ref:`ограничения выполнения <ai-architecture>`.

.. dropdown:: Как контролируется расход токенов по каждой LLM?
    :color: secondary

    Журнал «Вызовы LLM» ведётся в разрезе модели и провайдера (преднастройки группировки по моделям и по дням); отслеживается остаток квоты провайдера с предупреждением при 80 % использования. См. :ref:`Телеметрия и расход токенов <ai-telemetry>`.

.. dropdown:: Есть ли дашборды потребления токенов?
    :color: secondary

    Журнал «Вызовы LLM» с группировками по агентам, моделям, пользователям и дням покрывает типовые вопросы о расходе; сводная аналитика строится по данным журнала или штатными средствами мониторинга инсталляции. См. :ref:`Телеметрия и расход токенов <ai-telemetry>`.

.. dropdown:: Когда агент спрашивает человека?
    :color: secondary

    Утверждение плана, ошибки этапов, публикация конфигурации, изменение и удаление записей, расширение типов, уточняющие вопросы — полный нормативный перечень с настройками см. в разделе :ref:`Человек в контуре <ai-hitl>`.

.. dropdown:: Приходят ли уведомления о работе агентов?
    :color: secondary

    События агентов (публикация конфигурации, требуется подтверждение, результаты аудита) доставляются штатным механизмом :ref:`уведомлений платформы <notifications>` — почта, push, настраиваемые каналы; ход работы агента виден в чате пошаговым индикатором.

.. dropdown:: Может ли агент работать в BPMN-процессе?
    :color: secondary

    :ref:`AI задача <ai_task>` выполняет вызов LLM внутри процесса с подстановкой переменных и обработкой ответа скриптами; также из процесса доступен вызов преднастроенного агента-записи с его набором инструментов. См. также :ref:`режимы выполнения агентов <agent-execution-modes>`.

.. dropdown:: Насколько это безопасно?
    :color: secondary

    Лицензионный контроль, группы доступа, работа под правами пользователя, изоляция рабочих пространств и обязательные подтверждения необратимых действий описаны в статье :ref:`Безопасность AI-функций <ai-security>`.
