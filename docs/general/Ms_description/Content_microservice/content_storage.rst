Указание хранилища контента для типа
======================================================================

У каждого типа в системе можно задать, в какое хранилище контента будут сохраняться файлы из атрибутов с типом **content**.

.. dropdown:: Настройка хранилища для типа
   :color: secondary

   Для этого нужно сделать следующие действия:

   * Создать хранилище контента. Как это сделать описано в статье :ref:`Создание новой конфигурации файлового хранилища <content_new_config>`.

   * Зайти в журнал типов, затем найти тип и открыть его на редактирование.

   * Открыть вкладку **Конфигурация контента** и в свойстве **Хранилище** указать хранилище, в которое необходимо сохранять данные.

     .. image:: _static/content_8.png
         :width: 600
         :align: center

   * Сохранить изменения.

Эта настройка задаёт хранилище для новых записей контента данного типа. Выбор хранилища при загрузке выполняется вызывающим компонентом платформы, например ecos-model. Микросервис ecos-content получает конкретный идентификатор хранилища и возвращает ключ сохранённого файла.

.. note::

   Смена настройки не переносит существующие файлы автоматически. Доступ к ним сохраняется при условии, что прежнее хранилище, его конфигурация, endpoint и учётные данные остаются доступными для чтения. Переназначение того же идентификатора конфигурации на другой сервер само по себе не переносит данные и не гарантирует доступ к старым файлам.

   Поведение новой загрузки в уже существующую сущность определяется вызывающим компонентом. Поэтому смену хранилища не следует связывать только с датой создания сущности.
